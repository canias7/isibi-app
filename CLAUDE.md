## Structure

- Static frontend in `public/` (plain HTML/CSS/JS, no framework): `index.html` (the Zephyr chatbox — the only page), shared `styles.css` + `chat.js`, `auth.js` (Supabase email/password + email-code sign-in via GoTrue fetch, session in localStorage)
- `worker.js` — Cloudflare Worker: serves assets, `/api/video` + `/api/image` + `/api/audio` (fal.ai queue, per-kind model allowlists), `/api/direct` (director via ANTHROPIC_API_KEY, tool-use for structured output — Sonnet 5 rejects prefill; effort-routed: Haiku 4.5 writes Low/Medium compose/revise prompts AND the ask/error steps, Sonnet 5 handles High/Ultra/Max compose/revise (the `studio` step is dead code — Studio was removed, no client sends it); the ask step also returns `needsWeb`, and when true the frontend runs a `research` step — Sonnet 5 + Anthropic `web_search_20250305`, `max_uses:4`, ~$0.01/search — that returns a factual brief + sources folded into compose via `webFacts`, so "the newest X" gets depicted as the real current thing; gated behind that judgment so most generations never search), `/api/import/fetch` (gallery import-from-link: server-side fetch of a user-pasted URL behind auth + the SSRF guard/safeFetch, Chrome UA; direct image/video/audio → base64+kind back to the client; an HTML page runs `pageImageCandidates` — JSON-LD → og/twitter → microdata → link image_src → lazy-load/srcset `<img>` scan, candidates tried in order with retry — and when the free path comes up dry (bot wall or no image) it AUTO-FALLS-BACK to the paid AI lookup: Sonnet 5 + web_search finds direct image links / alternate open pages, **✦3 charged up front, refunded on any failure**, `scanai` quota 20/day, response carries `balance` for the pill; the client then pipes the base64 through the normal `/api/save` gates), `/api/video/poll` (proxies fal status/result so FAL_KEY stays server-side), `/api/save` (copies finished fal outputs into Supabase Storage `media` bucket using the caller's JWT). All `/api/*` require a Supabase-authenticated user (verified via GoTrue `/auth/v1/user`).
- Supabase project: fifa-tournament-hub (`ujrqdmmtcptvimazlhom`) — auth + public `media` storage bucket (INSERT-only RLS for authenticated users). Settings account controls: "Sign out on all devices" (GoTrue `logout?scope=global`) and "Delete account" (`delete_account()` RPC, SECURITY DEFINER auth-only — deletes chats/credits/usage_log/storage rows (via the `storage.allow_delete_query` GUC)/GoTrue child rows/auth user; **`purchases` are deleted too** — full wipe on account deletion is the owner's call (2026-07-15), so `purchases.user_id` cascades with the auth user by design; client wipes its storage files via the Storage API first, then every `zephyr_*` localStorage key)
- Chats persist in localStorage (`zephyr_chats_v1`, 30 chats × 80 msgs) AND sync cross-device to a Supabase `chats` table (pushChats/pullChats); media messages store the permanent Supabase Storage URL. **Avatars sync cross-device too (2026-07-16)**: one `user_assets` row per user (avatars jsonb, RLS own-row, FK-cascades on account deletion; the table's `products` column is orphaned since the Products removal — harmless, ignore it), whole-object last-writer-wins like `user_memory` (pushAssets debounced from saveAvatars, pullAssets at boot); images are compacted to ≤800px JPEG before push (hosted URLs pass through), so the originating device keeps full-res locally until another device edits
- **Media Agent** — Instagram/YouTube manager (Composio, `COMPOSIO_API_KEY` server-side). Analytics/Posts/Comments (read) + **comment auto-reply** (prompt-driven, cron every 2 min, Haiku drafts, `INSTAGRAM_POST_IG_COMMENT_REPLIES`) are live; DM auto-reply is blocked (Instagram `instagram_manage_messages` needs Meta App Review). **A "Schedule post" tab (Instagram only) was added 2026-07-17 — FRONTEND ONLY: compose media+caption+datetime → a local queue in `localStorage` (`zephyr_ig_scheduled_v1`), nothing publishes yet. Media is previewed locally (no upload). Backend wiring (Composio create-post at the scheduled time + persistence) is the pending next step — the composer carries a "Preview · not published yet" flag.** Config in `user_autoreply`, dedup in `autoreply_log`, cron gated by `AUTOREPLY_ALLOW`. **For tool permissions, rate limits, engine caps, cost, and the scaling concern → see `docs/media-agent.md` (pull it up when the user asks any of that).**
- **Universal memory** — a **backend/system feature with NO front-end** (user's call): auto-learned creative taste, applied to EVERY generation across all chats (not per-chat). It learns from BOTH generations and plain conversation: the **ask** step (runs on every chat message) returns an evolved `memory` list that commits immediately (no approval gate — chat itself is the signal), and the **compose/revise** `write_prompt` tool also returns one that commits on approval (`pendingMemory`→`commitMemory`, mirroring the brief). Both feed compose/revise/ask via `directorContext().memory` → `memoryLine` in the worker (≤12 short durable phrases, project-specifics excluded). Stored in `zephyr_memory_v1` + a per-user `user_memory` Supabase row (items jsonb, enabled bool, RLS own-row; pushMemory/pullMemory last-writer-wins; in `delete_account` + the local wipes). Gated off for audio. **No UI at all** — the Memory floating button and its `viewMemory` "space" page were removed; the feature is entirely invisible/backend.

## Working rules

- **Always show UI changes as screenshots in the chat** (render the page headless and send the image) — the user reviews everything visually here.
- The user directs design; don't restyle beyond what's asked.
- Don't spend fal credits or Workers AI calls on tests without asking first.
- **The website-builder component kit is TypeScript. New components go in `builder/template/src/components/` as `.tsx`, never `.jsx`** (owner's call 2026-07-24). Type the props (`interface XProps`), use the shared shapes in `src/lib/types.ts` rather than redefining them, and add the component to `COMPONENT_INVENTORY` in `builder/react-gen.mjs` in the same commit — a component missing from the inventory is invisible to the generator. `node builder/check-kit.mjs` enforces all three and runs in CI (`kit-check.yml`); run it before committing kit changes.
- Generated app pages are `.tsx` too, with LIGHT annotations only — measured overhead is ~0.5%, and it stays that way because page components take no props and `useState` infers. Don't annotate every local.
- **Whole-app STARTERS (added 2026-07-25) — the layer above page recipes.** `builder/starters/<id>/` holds a complete, working app (pages + optional `lib/` + `isibi.schema.json`) authored as real `.tsx` files; `node builder/build-starters.mjs` compiles them into the worker-safe `builder/starters.data.mjs` (commit both — `check-kit.mjs` fails if it is stale). `builder/starters.mjs` exposes `matchStarter/getStarter/starterFiles/starterBrief`; matching DELEGATES to `capability-bundles.mjs` so the backend bundle and the front-end starter can never disagree. When one matches, the pipeline seeds it for $0 (routing + palette are already free via `scaffoldRouting`/`scaffoldTheme`), step 1 becomes an ADAPT edit instead of a from-scratch SHELL, and every capability in the starter's declared `covers` is never generated. Each starter declares `navOrder` because alphabetical nav put Cart before Shop. Live: **booking, commerce, content, crm, helpdesk** (29 pages); still generating from scratch: social, events, directory, loyalty, courses. The CRM and help desk use the platform's own table features — `teamRead` (a manager reads their whole downline via `_users.manager_id`; writes stay own-row), `transitions` (stage/status gating enforced server-side), `sequence` (TKT-0001), `sla`, `trash` — so the starter's UI only ever offers a move the server will accept. `check-kit.mjs` validates starter imports, blocks raw `api.*` calls on `/rows` (everything goes through `useResource`), and CI typechecks every starter against the kit.
- **Five kit components are Radix-backed (added 2026-07-25): `Modal`, `Dropdown`, `Popover`, `Tooltip`, `MultiSelect`.** Their PROPS are unchanged — every call site and generated page was untouched — but underneath they are `@radix-ui/react-{dialog,dropdown-menu,popover,tooltip}` so they get focus trapping, arrow-key menu nav, Escape, `aria-describedby` wiring and collision flipping. We did NOT adopt shadcn/ui: it is a ~50-component primitives library and our value is the 250 domain components on top, plus its compound API (`<Select><SelectTrigger>…`) costs more output tokens per page. Cost measured on the 6-page booking starter: 90.5 kB → 104.1 kB gzipped (+13.6 kB). `check-kit.mjs` asserts each of the five still imports its Radix package — the props didn't change, so a "simplification" back to a plain div would break nothing visible.
- **`publicView` — a declared PII-filtered projection of an owner-scoped table (added 2026-07-25).** `"publicView":{"columns":["date","time"],"where":["status:eq:confirmed"]}` on a table exposes `GET /rows/<t>/public` to anyone, returning ONLY those columns. Closes the hole where a `user`-scoped `bookings` table meant the booking form could not know real availability. Columns are an explicit allow-list; `id`/`owner_id` rejected at declaration; a caller may filter only on published columns. Read it with `usePublicRows(table, params)`. Handler + parser in `worker.js`; eight security properties covered by a test that lifts the real code out of worker.js.
- **Row types are GENERATED from `isibi.schema.json` (added 2026-07-25).** `scaffoldDbTypes` emits `src/lib/db-types.ts` at build time ($0), and `useResource('bookings')` resolves its row type from it — so `data[0].customer_name` is checked with no annotation, a column typo is a compile error, and an `enum` column becomes a literal union. Unknown table names still fall back to `any` so a build never dies over a table the schema hasn't caught up with. `create`/`update` take `Partial<Row>` ONLY — the original `| Record<string, any>` escape hatch silently defeated the whole thing, and check-kit now blocks it coming back. **Knock-on fix:** `usesBackend()` (the schema-fix trigger, in BOTH `full-pipeline.mjs` and `worker.js`) matched the literal `/rows/` in page source — which `useResource` no longer emits, so it now also matches `useResource(`/`useRecord(`.
- **`AGENTS.md` is generated into every app (added 2026-07-25)** — `scaffoldAgentsMd`, $0, describing THIS app's tables, pages and which files are code-generated. Copied from Lovable: without it, a customer who downloads the repo hands their own coding agent 258 unfamiliar components and no rules.
- **Generated pages read/write the backend through `useResource`, never hand-rolled fetch state** (added 2026-07-25). `builder/template/src/lib/useResource.ts` wraps TanStack Query — the hook is the interface, the library is the engine — and exposes `{data, total, loading, error, saving, create, update, remove, refetch}` plus `useRecord(table, id)`. Writes invalidate the table's cache themselves, which kills the commonest silent bug (a create that saved but never refreshed the list). `QueryClientProvider` is mounted once in `template/src/main.tsx`; `check-kit.mjs` asserts both the provider and the documented return keys, so the rules can't drift from the hook.

## Credits & monetization (live)

Every generation is metered in credits (1 credit = $0.008 fal cost). Postgres RPCs (all SECURITY DEFINER, auth-only): `get_credits()` / `use_credits(cost)` (grant **20** credits on first touch), `add_credits(target,amount,cents,ref,mint_key)` (**service_role-only** EXECUTE, mint-key gated, idempotent on `purchases.ref` — called only by the Stripe webhook with the service key), `credit_back(target,amount)` (**service_role-only**, ≤10 credits/call — reverses an orchestrator fee when the Claude call failed; no purchases row), `is_paid()` (has-ever-purchased). **Credits are `numeric(16,6)` (fractional, migrated 2026-07-14)** — `use_credits`/`get_credits`/`add_credits` are numeric-typed; generations still charge whole credits (`ceil(fal_usd/$0.008)`), but the **AI Orchestrator is metered per-call through the same ledger** (no longer a subscription): `/api/direct` charges `orchestratorCostMicros(step,effort)/8000` credits at the gate before the Claude call (ask 0.375 · prompt/error 0.5 · compose/revise High+ 3.125 · research 4.375), 402→client falls back to raw. The **Orchestrator + Video Editor $19.99/mo add-ons were removed 2026-07-14** (Video Editor gone entirely; Orchestrator on for everyone, no padlock, spends credits). Only Plus/Pro/Max memberships + top-ups remain. Worker: `/api/credits` returns `{balance, paid}`; charge-AFTER-fal-accepts flow (readCredits → fal submit → useCredits → cancelFal on race). `/api/checkout` (Stripe subscription/one-time session) + `/api/stripe/webhook` (verifies the `Stripe-Signature` HMAC, mints via `add_credits` with the service_role key on `checkout.session.completed` for top-ups and `invoice.paid` for memberships). **Stripe activated 2026-07-08** — the four payment secrets (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `CREDITS_MINT_SECRET`, `SUPABASE_SERVICE_KEY`) live in GitHub Actions and upload to the Worker each deploy; the webhook endpoint is `https://isibi.ai/api/stripe/webhook` listening for `checkout.session.completed` + `invoice.paid`. The `private.mint` singleton holds the SHA-256 of `CREDITS_MINT_SECRET` (rotated 2026-07-08). Free accounts (`!is_paid`) get watermarks: images burned in client-side (canvas → JPEG → `/api/save` base64 path, server rejects raw-URL image saves for free users), videos get an on-screen badge on every playback surface (chat player, gallery card, lightbox) — the FILE itself is still clean; the fal blend-video burn is designed and its CI test bench is committed (`.github/workflows/fal-wm-test.yml`, runs on pushes touching its own files) but blocked on the fal balance top-up. Pricing page = `openCredits()` (three tiers Plus/Pro/Max at $24.99/$49.99/$99.99, rolling launch-offer countdown); top-ups = `openCredits(true)`. **Gallery storage is a subscription benefit (added 2026-07-08)** — saving to the gallery requires a paid tier, capped by size: **Plus 10 GB · Pro 50 GB · Max 100 GB** (GiB-bytes). DB: `user_plan` table (tier + plan_until, RLS own-select), `set_plan(target,tier,until,mint_key)` (mint-gated, called by the webhook `invoice.paid`, tier derived from minted credits, plan_until = now+32d), `storage_status()` RPC → `{used, cap, tier}` bytes (lapsed plan_until → free/cap 0; sums the caller's `storage.objects` under `media/<uid>/`); `delete_account()` also clears `user_plan`. Worker: `storageStatus()` helper + `GET /api/storage`; `/api/save` returns **402** `{reason:"free"}` when the account has no storage (free/lapsed/top-up-only, cap 0) and `{reason:"full"}` when the new object would exceed the cap (fails open if the ledger is unreachable). Frontend: gallery usage bar (`galleryStorage`, `refreshStorageBar`/`paintStorageBar`, tier badge + warn/full tint, upgrade CTA when cap 0 or full); `trySave` treats 402 as terminal (returns a `block` field: `'free'`/`'full'`) — no doomed retry queue, delivers the media on a temporary link with a friendly note. **Edge case:** a top-up-only buyer (credits but never a membership) has cap 0 → can't save; only memberships grant storage. **Gallery import (2026-07-16):** the gallery header has an ⤒ Import button (device files, ≤12/batch, image/video/audio, client caps 8.5/29/14 MB → `/api/save` base64 — an audio b64 branch was added, MP3/WAV/OGG/M4A by magic bytes, ≤20M chars) and an import-from-link box (`.gi-url` → `/api/import/fetch` → `/api/save`); both are storage-gated like every save (cap 0 → `openCredits()` client-side, 402 server-side). Errors surface via `sbToast` (bottom-center toast, defined 2026-07-16 — earlier guarded callers were silently no-oping).
