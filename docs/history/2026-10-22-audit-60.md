# Audit finding A35-1 (2026-10-22): a preparation keeps no question

From `docs/audits/2026-10-17-builder-audit.md`, re-checked on `codex-work-into-claude` (`fdf73825a`). Branch `audit-60`. Offline; nothing spent, merged or deployed.

## The finding, checked again

- **Real.** `runRequestPrep` prepares a part's run step through `replayPrepared`, which calls `handleRequest` with the real `SITES_BUCKET`. The edit and add-on routes end in `askReport`, which had no preparation guard: with `ePart`/`aPart` set (read for any job, preparations included) it stored the step's question in the site's slot under a fresh id (`storeAskIfFreeTwice`). The preparation itself only records `outcome: "ask"`. When the part's job replayed the step it asked under a new id, `storeAskIfFree` refused it (a different pending question held the slot), so the part waited on a question marked `queued`, which the page never draws. `makePrepCtx`'s doc already said "no question is kept"; only the routing preparation honoured it.
- **Reproduced through the real route** (P4 in `test/parallel-requests.test.mjs`, supplied model answers): on the old code `s1.rec.parts[1].question.queued === true` and the slot's id differs from the part's, exactly as the audit predicted. P4 passed before only because it answered with the slot's id.

## Fix (`worker.js`)

- `askReport` returns the route's answer untouched when `ctx.prep === true`. The preparation still reads `ask` from that answer as its outcome; nothing is stored.
- The edit route sets `eAskOut.prep` when `eJob.prepare === true`, the add-on route `aAskOut.prep` when `aPrep`; both pass `prep` to `askReport`.
- The part's own job (not a preparation) stores its question as before; with the slot free it is kept, not queued, and the page shows it.
