## A14-6 — held database changes said as made (dormant: PROGRESS_REPLIES off)

- **Re-verified.** The publish lines already said "Saving … to their draft"
  (2026-10-19). Still wrong under draft-first: a held row or rule step said
  "Changed in the site's database" (`editPublishFacts`, `editStepFacts`,
  `editAppliedFacts`); an add-on's held schema "Created in the site's
  database" and its seam "Publishing the site"; the opening plan "… and it is
  published" (edit, add-on, build).
- **Fix** (`builder/site-progress.mjs`, `worker.js`). A database step whose
  answer carries the held draft (`heldDraft`: published false, held true) is
  said "Held in their draft, not in effect yet … It takes effect when they
  press Publish." (`prepared`). `addonSchemaFacts` takes `held` (the schema,
  `aWriter.holding`), `heldJobs` (timers, `aWriter.on`, as `backendWriter`
  holds them) and `draft`. `startFacts` takes `draft`; all four start marks
  pass `draftFirst(env)`. Off, every line is as before.

## A36-2 — the conversation was told "no database tables"

- **Re-verified.** `readConverseContext` listed `spec.spec.tables` only, so
  `tables-without-metadata` (spec `{tables: []}`) read "It has no database
  tables." while the router was told the catalog's names; a live table missing
  from a stored spec was never named.
- **Fix.** `converseTables(st, label)` in `builder/site-converse.mjs`: the
  spec's tables with columns and access, plus every name in `missing` with the
  catalog's columns and "access not recorded"; identifier-shaped names only;
  `null` when unreadable. `readConverseContext` calls it with `accessLabel`.

## A36-3 — a go-ahead on a long plan was cut at `max_tokens`

- **Re-verified.** With a conversation shown the router's ceiling was
  700 + echo(message) + 400, whatever `resolved` had to restate.
- **Fix** (`builder/site-ask.mjs`). Plus twice the longest shown turn
  (`echoTokens`); the router's window caps its last reply at 3,200 characters,
  so at most 3,200 more tokens, a ceiling only. `test/model-limits.test.mjs`'s
  floor check and `test/conversation.test.mjs`'s exact ceiling updated.

## A36-4 — the conversation was not told about drafts

- **Re-verified.** No draft or Publish wording in either prompt; the stored
  pages (the draft) were "the site".
- **Fix (the conversation only).** `readConverseContext` returns
  `draftFirst`; `siteContextBlock` then says every change is saved to a draft,
  goes live only on Publish, the pages are as saved, and never to call a change
  live unless published.
- **Left for the owner: the router's digest** (`siteDigest`), because the
  router's wording is lane 3's, after the owner's decisions. Options: (a) add
  the same one-sentence draft fact to `siteDigest` under draft-first, with
  "publish my changes" described as the Publish button (recommended, small);
  (b) leave routing as is and rely on the page's Publish button; (c) route a
  typed "publish" to a fixed rule that opens the Publish panel.

## A36-5 — a part's routing job lost the table names

- **Re-verified.** `jobBody` blanked `rec.digest.tables`; `routeDigest` keeps
  the caller's names only when its own read answers `null` (timeout, throw),
  so a failed read left the router with none.
- **Fix** (`builder/request.mjs`). The names known at acceptance are kept; the
  route still replaces them whenever its read answers (an empty list included).
  `test/request-plan.test.mjs`'s body case updated.

## S5-3 — "Saved" while a request part was still being prepared

- **Re-verified.** `readState` counted only `edit_jobs` rows; a part prepared
  in the Worker has none.
- **Fix.** `requestMaking(rec)` (`builder/request.mjs`): a part queued,
  started, ready or recovering, or one whose preparation is running
  (`prepState`). `requestsMakingFor` (`worker.js`) reads this owner's unended
  request markers for the site (`requests-live/<slug>/`, 50) and the draft
  route adds the count to `running`. A read that fails counts nothing.
  Display only (the chip, the panel's processing note, the page's follow).
