# Audit findings A03-6 and A04-6 (2026-10-22)

Two findings from `docs/audits/2026-10-17-builder-audit.md`, both re-verified
as still real today on `codex-work-into-claude`, fixed one commit each on
`audit-84-88`. Offline; nothing spent, no deploy, nothing pushed to `main`.

## A03-6 — renaming the business missed the site's own components

- **Finding (re-verified).** The look step's rename (`renamePages`) was handed
  `qrCut ? qrCut.pages : eSrc`, the pages only. On a site split into bands the
  visible copy lives in `-parts/` components, so the hero and footer kept the
  old name; the publish sent no renamed parts, and the reply's `renamed`
  counted pages only. Driven through the route: the hero still read the old
  name after a reply of `ok`.
- **Fix** (`worker.js`, look rung). When the brand moves, the site's
  components are read before the look is written (`editParts`); an
  unreadable store refuses with `parts-unreadable`, cost 0, nothing stored or
  published (the text rung's rule). The rename runs over
  `editableFiles(pages, parts)` (the parts a QR removal already read, when
  one did), the result is split back with `splitEditable`, and both halves
  are published. `renamed` counts the files whose prose changed. The same
  `renamePages` (prose only, via `extractText`) does the rewriting, so link
  addresses and code are untouched.
- **Tests** (`test/look-rename-parts.test.mjs`, 8 cases, sync and queued,
  through the real edit route): components renamed, prose only, untouched
  component kept, publish carries the renamed parts, count 2; unreadable
  store refused before writing; a site with no components still renames its
  pages (control); a rename beside a QR removal renames the components that
  removal read. One spelling guard in `test/site-apply.test.mjs` pinned the
  old call and now pins the new one.
- **Red check.** 4 of the first 6 fail on the old code (the 2 controls pass).
- **Sweep.** 5 of 5 mutants killed (pages only; no refusal; parts not
  published; no read; the QR removal's parts ignored, killed after the
  eighth case was added); the comment-only control survived.
- **Full suite** (`node --test "test/*.test.mjs"`, before the guard update):
  11,840 tests, 11,834 pass, 3 fail, 3 skipped. The fails: the spelling guard
  (updated); `no-generated-deps` (caused by the temporary `node_modules`
  symlink this run needs; removed before commit); `media-verify`'s browser
  case, which passes run alone (load-sensitive, unrelated).

## A04-6 — a photo addition was planned and written while purchases were off

- **Finding (re-verified).** The add-on's pre-page-call photo gate (`aShots`)
  read only the balance (`imagesAffordable`), never `imagePurchasesOn(env)`;
  only `makeSitePhoto` read the switch, after the page call. Driven through
  the route with `IMAGE_PURCHASES=off`: the page writer was called, then the
  purchase refused and the reply said "I couldn't get a photograph to put
  there just now", which invites a retry that cannot succeed.
- **Fix.** `worker.js`: with the switch off no shot is offered (`aShots` is
  empty and the balance is not read), so a photograph-only addition with
  none of the site's own photographs is refused by the existing early check,
  before the page call, at cost 0. Beside a page, the writer is no longer
  shown photo tokens that could only become placeholders.
  `builder/site-add.mjs`: `noPhotoMsg({ purchasesOff })` says "New
  photographs can't be made for sites at the moment, so nothing on your site
  changed. I can place one of the photographs your site already has instead
  — tell me which." The old sentence is kept for the switch on.
- **Limit, said plainly.** The picker and the photo designer still run before
  the refusal: the designer is what decides whether one of the site's own
  photographs can be placed (`aFold.reuse`), which works with purchases off,
  so refusing before it would refuse a request that can succeed. The page
  writer, the expensive call, no longer runs.
- **Tests** (`test/addon-route.test.mjs`, 2 cases through the real add-on
  route): switched off, a photograph alone is refused before the page call,
  no shot, no compile, cost 0, and the sentence has no "just now"; control:
  switched off, one of the site's own photographs is still placed.
- **Red check.** The refusal case fails on the old code (the page writer was
  called); the control passes on both.
- **Sweep.** Killed: the old sentence; the switch read inverted (18 fails);
  both walls cut together. Survived, explained: the `aShots` wall alone and
  the balance-read wall alone. They are two walls on purpose (with the
  balance unread it is 0, so `imagesAffordable` offers nothing), and cutting
  both is killed. Comment-only control survived.
- Related files (`addon-route`, `addon-row`, `site-add`,
  `addon-failure-outcome`, `progress-gaps`): 410 / 410 pass.
- **Full suite** (both fixes, with the A03-6 guard update): 11,844 tests,
  11,840 pass, 1 fail, 3 skipped. The one fail is `no-generated-deps`,
  caused by the temporary `node_modules` symlink; it passes once the
  symlink is removed (checked before commit).
