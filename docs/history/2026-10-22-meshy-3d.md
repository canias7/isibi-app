# 3D models with Meshy 7.1 through fal (2026-10-22)

The owner (2026-10-22): when a customer asks for a 3D asset, unless they ask
otherwise, the model is made with fal's Meshy 7.1 and shown with three.js
through the kit's `Scene3D`. Branch `claude/meshy-3d`, from
`claude/scene3d-kit-component` (`3f903a86`). Offline only: no fal request, no
model call, no deploy.

## What was built

| Part | Where |
|---|---|
| Request builders, answer reader, price, fal queue flow, capped download, page placement, reply | `builder/site-3d.mjs` (pure) |
| The route's logic: estimate, start (debit, submit, record), poll (status, finish or refund) | `builder/model3d-route.mjs` (deps injected) |
| Owner route `GET/POST /api/site/<slug>/model3d`, its deps, `storeOwnFile` | `worker.js` (matcher `m3d` in the owner block, `assertOwner` first) |
| A `.glb` / `.usdz` upload kind with its own allowance | `site-uploads.mjs` |
| Router field `model3d` beside intent `addon`, reader `readModel3d`, reason `model3d-unread` | `builder/site-ask.mjs` |
| The routing reply forwards `model3d` (both the prepared and the live reply) | `worker.js` |
| The price card, the progress lines, the reply | `public/chat.js`, `public/styles.css` |
| The page writer's 3D paragraph: a stored model through Scene3D, only where asked | `builder/page-gen.mjs` |
| The container's worker tree carries the two new modules | `Dockerfile` |

## The fal side

- Endpoints: `fal-ai/meshy/v7.1/text-to-3d` (`prompt`, at most 600 characters,
  `mode: "full"` for the textured model) and `fal-ai/meshy/v7.1/image-to-3d`
  (`image_url`, `should_texture: true`). Parameter names read from fal's API
  pages on 2026-10-22.
- Settings for websites: `model_type: "smart-topology"`, `target_polycount:
  12000` (fal's ceiling for smart topology is 15,000), `topology: "triangle"`,
  `symmetry_mode: "auto"`, `enable_pbr: false`, `enable_rigging: false`,
  `enable_animation: false`, `enable_safety_checker: true`.
- Always the queue: `POST https://queue.fal.run/<model>`, then
  `…/fal-ai/meshy/requests/<id>/status` and `…/requests/<id>` for the result
  (fal addresses a request under the app id). Status and result URLs fal
  returns are used only when their host is `queue.fal.run`. Never `fal.run`.
- The answer: `model_glb` (or `model_urls.glb`) must be https or the
  generation is a failure; `model_urls.usdz` and `thumbnail` are kept when
  https, dropped otherwise.
- The key is the platform's `FAL_KEY`, the one the photo purchases use.

## The money

- 150 credits (`MODEL3D_CREDITS`, $1.20 / $0.008). Shown first (`GET
  ?estimate=1`, with the balance); the debit is exactly that and never more.
- `POST` debits under `model3d:<slug>:<key>` (`debitCredits`, not partial):
  a short balance is refused by the ledger with nothing taken, before fal is
  called. The same key again answers from its record: no second debit, no
  second submit.
- Reversed in full by that ref (`reverseCredits`, reason `model3d-refund`)
  when fal refuses the submit, when the generation fails, or when the `.glb`
  cannot be downloaded (over 50 MB) or is not glTF. The finish claims the
  record over its etag, so two polls cannot both refund or both publish.
- A model that was made and stored stays charged when the page could not take
  it (no `</SiteChrome>` frame, or the publish failed); the reply says so.
- Switch: `MODEL3D_PURCHASES=off` refuses before anything is charged. Absent,
  it is on wherever `FAL_KEY` is set.

## Storage

- `.glb`: sniffed by its own magic (`glTF`, version 2), stored as
  `model/gltf-binary`. `.usdz`: a zip whose declared name is `usdz`, stored as
  `model/vnd.usdz+zip`. `/u/` serves the stored type, inline.
- Own allowance: 50 MB a file, 40 files, 500 MB a site; pictures and documents
  do not count models and models do not count them. The owner's upload route's
  outer bound is now 50 MB (the largest kind it takes whole); the Files panel's
  picker has no `accept` filter, so an owner can upload a `.glb` too.
- The poster (fal's thumbnail PNG) is an ordinary picture upload.

## On the page

`placeScene3D` adds `import { Scene3D } from "@/components/ui/scene-3d";` once
and a band before the page's last `</SiteChrome>`:
`<section className="mx-auto max-w-6xl px-6 py-16"><Scene3D label={…} src={"/u/<slug>/<hash>.glb"} poster={"/u/<slug>/<hash>.png"} height={420} /></section>`.
Values are JS string literals. Nothing else in the page changes. Then the text
route's spine: `loadSiteSourceForEdit(…, { checked: true })` and
`recompileAndPublish` (label "Added a 3D model").

## From the chat

The router's live tool has a typed `model3d` field (`from: words | photo`,
`subject`, `page`) beside intent `addon`. `readDecision` reads it on an
addition only; an unreadable one is left out with `model3d-unread` and the
addition runs as before. The page, on an addition with `model3d`, asks for the
price, shows the card ("Make it · 150 credits", "Not now"; disabled with a note
when the balance is short), and only the button POSTs. It then asks every 6
seconds and adds a line when the state changes ("Making your 3D model…",
"Started — 150 credits reserved…", "Waiting in line…", "Shaping and
texturing…", "Saving it to your files and putting it on /shop…"), and the
reply names the cost.

## Not shown yet

- No real fal request was made: the answer's real shape (File objects), the
  queue's real timing and the real file sizes are read from fal's pages, not
  measured. One paid run (about 150 credits, $1.20) on a test site would show
  them.
- The request stays on the customer's connection only for the publish on the
  finishing poll (a container compile, as the text route); generation itself
  is polled, never held.
- A refund that fails on the first try is recorded (`refunded: false`) but not
  retried by a sweep.
- The image rolls (worker.js, site-uploads, site-ask, page-gen and the two new
  modules are container inputs).
