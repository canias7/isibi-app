## Per finding

### A26-2 — removing the logo through the look door left a legacy upload showing
- **Verdict**: real. The look step's merge wipes a removed field to `null`,
  and `markOf` reads a stored `null` as "no form" and falls back to
  `config.logo` / `config.icon`.
- **Fix** (`worker.js`, the look step): after the merge, a removed `wordmark`
  or `favicon` that merged to `null` is stored as `markRemove(config, field)`,
  the form the logo rung already stores. The stored config is kept beside
  `priorLook` (`priorConfig`) for it.
- **Test**: `test/look-mark-removal.test.mjs` (LMR1, both marks), driven
  through the real Worker (request flow, supplied answers) on a config with
  the old `logo`/`icon` keys.
- **Red check**: 0 of 2 pass on the unfixed `worker.js`.
- **Sweep**: 4 of 4 killed (assignment dropped, condition negated, take-off
  test flipped, `=== null` inverted); control survived.

### A26-3 — a PDF beside the logo was refused as "several files"
- **Verdict**: real (`runLogoEdit` counted every attachment with `data`).
- **Fix** (`builder/site-logo.mjs`): a data URL declaring a non-image type is
  not a candidate; two or more pictures are still refused; with no picture the
  first file is still read and refused for what it is.
- **Test**: `test/site-logo.test.mjs` "A26-3: …" (picture + PDF stored; two
  pictures + PDF refused as 2; a lone PDF `unreadable`).
- **Red check**: 1 failing on the unfixed file. **Sweep**: 4 of 4 killed,
  control survived.

### A26-4 — a first build cannot put an attached logo in the header
- **Verdict**: real gap, still true (`WORDMARK_FIELD` is `text` or an SVG; only
  `images[].attached` places a build attachment, as a page photograph).
- **Not changed: it needs the owner's decision.** Options:
  1. A design field naming which attachment is the logo; the build stores it
     as the logo rung does (`uploadKey`/`uploadUrl`) and sets
     `look.wordmark = {form: "image", url}`. Full feature, one model field.
  2. No model involvement: when a build brief has exactly one image attached
     and the brief says "logo", store it as the wordmark. Cheaper, but a
     keyword rule (the working rules forbid those).
  3. Say it in the build reply: "send the logo again as a logo change".
  - Recommendation: 3 now (free, honest), then 1.

### A27-3 — a footer contact edit deleted fields it could not read
- **Verdict**: real.
- **Fix** (`builder/site-nav.mjs`): `chromeObjectUnread` — a contact or layout
  object holding a known non-enum field the reader could not read (a constant,
  single quotes, a template literal, a bare variable) is not a slot, so the
  writer never re-serialises it. The rule `navSlots` already lives under.
- **Test**: `test/nav-chrome-audit.test.mjs` A27-3 (the audit's probe object;
  plus a plain-string control still merged field by field).

### A27-4 — a comment inside a menu or footer list hid it
- **Verdict**: real.
- **Fix** (`site-nav.mjs`): `splitTop` skips comments as `arrayEnd`/`braceEnd`
  do (one between elements is dropped from the parts); `chromeListSlots` no
  longer offers an insertion point on a page whose `social`/`legal` array is
  present but unreadable (no second key).
- **Not changed**: naming, in the reply, a page whose menu could not be read
  (a reply change; with the comment case fixed the remaining unreadable menus
  are spreads and computed values, refused by design).
- **Test**: two A27-4 cases in `test/nav-chrome-audit.test.mjs`.

### A27-5 — footer email icons were deleted and could not be added
- **Verdict**: real.
- **Fix** (`site-nav.mjs`): `listHrefProblem` — a footer list entry (social,
  legal; in `readNav` and `readAdditions`) also takes a bounded `mailto:`
  (one address, no query); a malformed one is refused as `bad-address`, with
  its own sentence. The menu's rule is unchanged.
- **Test**: A27-5 in `test/nav-chrome-audit.test.mjs` (restated list keeps the
  email entry; an addition is accepted; four malformed forms refused; a mailto
  in the menu still refused).

### A27-6 — NavFooter columns were read as menus
- **Verdict**: real.
- **Fix** (`site-nav.mjs`): `navSlots` skips a `links` array inside a
  `columns`/`groups` array (the key, the JSX prop, or a constant named for it,
  `const COLUMNS = [`), each measured by `arrayEnd` from its own bracket.
- **Test**: A27-6 in `test/nav-chrome-audit.test.mjs` (only the real menu is a
  slot; a menu addition lands only there).
- **Red check (A27-3/4/5/6)**: 0 of 5 pass on the unfixed `site-nav.mjs`.
- **Sweep**: 7 of 7 killed, control survived.

### A27-7 — the menu step cannot be scoped to one page
- **Verdict**: real gap, still true (`runNavEdit` takes no page; the tool says
  "the same menu on every page").
- **Not changed: it needs the owner's decision.** Options:
  1. A `pages` scope on removals, renames and moves (as `add` has), applied
     only to those pages' slots, and the router's or picker's page passed in.
  2. Tell the model to ask back whenever a single page's menu is named.
  3. Leave it: one menu for the site, and say so when a page is named.
  - Recommendation: 1 (the site already keeps a different menu per page);
    2 is a prompt-only stopgap.

### A27-8 — a menu write ran beside a page write and always lost at publish
- **Verdict**: real.
- **Fix** (`builder/request-plan.mjs`): `besideConflict` refuses a part that

  running side by side changes; preparation order (`conflicts`) is untouched
  (changing `overlaps` instead broke four preparation tests: P3b, R11 ×2,
  `routedForPrep`). A page rename writes `menu`, so this also keeps a rename
  from running beside another page writer.
- **Test**: BC2 in `test/request-beside.test.mjs`.
- **Red check**: 1 failing on the unfixed file. **Sweep**: 4 of 4 killed,
  control survived. Affected files (beside, parallel-*, request-*, door-turn):
  420 / 420.

### A31-1 — "forget the old address" breaks the site's own QR codes

- **Not changed: it needs the owner's decision.** Options:

### A31-7 — wifi codes were never checked
- **Verdict**: real.
- **Fix** (`builder/site-qr-list.mjs`): `readQrText` refuses a `WIFI:` payload
  whose fields do not read back (every field `KEY:value`, a network name
  present, no dangling `\`); the add-on and look prompts now say a `;` or `\`
  in a network or password gets a `\` before it. A `:` or `,` in a value is
  left alone (common readers end a field only at `;`). Fixtures in
  `test/addon-route.test.mjs` and `test/site-add.test.mjs` used `S=`/`T=`/`P=`,
  a malformed wifi string; corrected to `S:`/`T:`/`P:`.
- **Test**: A31-7 in `test/qr-audit.test.mjs`. **Red check** (A31-5 and A31-7):
  each fails on its unfixed file. **Sweep**: 4 of 4 killed, control survived.

### A33-3 — an unreadable previous sidecar erased every redirect
- **Verdict**: real.
- **Fix** (`worker.js`): the previous sidecar is read once more on a failed
  read; if it still cannot be read, `composePublish` throws, and the edit
  spine answers it as a stage failure (ours, `transient`, uncharged, nothing
  live-changed). A missing sidecar (a first publish) is unchanged. The build
  path's publisher already reads a throw as its failure.
- **Test**: two A33-3 cases (sync, job) in `test/publish-redirects.test.mjs`,
  through the real edit route: the compose step's reads fail (found by their
  own stack frame), the publish is refused (the job refunded), no version goes
  live, the stored redirects stay; control: one failed read then a good one
  publishes and keeps them.
- **Red check**: 0 of 2 pass on the unfixed `worker.js`.
- **Sweep**: 4 of 4 killed (after the test was tightened to target the compose
  step's read: the first version let the no-retry mutant survive, because
  other steps read the same key), control survived.
- **Known wording limit**: the customer is told the existing stage sentence
  ("our build service was restarting"), not a sentence about the read.
