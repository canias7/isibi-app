  people, max 8 per group lesson, and a switch … closed for bad weather") ran
  as add-on job `df8fee86…` (trace `e_mvnbujerhycdempb`) **with** the

  cleaner refused the empty list (`nothing`), and the job failed: "Still to
  do: …".
- The "designed nothing" retry (round 2 of the retry rule) tested only
  `ran.value === undefined`, so it never ran (no `retry_reason` in the trace).

  `e2486dd6` (`writes: data:lessons`, no page written, so no hand-over,
  correctly) and ran alone as rows: job `dc143ad0` wrote lessons 9–12.

Root cause: the component designer never saw the hand-over (`handOverLine`
reached the picker only), and its empty design was not retried.

Fix (`builder/addon-existing.mjs`, `worker.js`):

- `featureBrief(hand, kind)`: under `feature-on-page`, the component
  designer's brief says the feature is new on that existing page, is built
  here as a component, and is not handed to the page step. Added to both the
  early-start brief and the turn's brief.
- `designedNothing(value)`: absent, null, an empty list or a list with no
  object. Under `feature-on-page` on the component step, an empty design takes
  the existing decline retry (`aEmptyFeature`). Elsewhere an empty list stays
  the model's own decline (validation-reuse VA 4 and VA 6, which failed when
  this was applied everywhere, are kept).
