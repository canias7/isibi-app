## Part A — the review's five findings

Each has a guard that failed before the fix (shown by running the guard over
the earlier code), and a sweep of four mutants plus a comment-only control
that survived.

1. **HIGH: a visitor's `{{API_KEY}}` was filled with the owner's secret**
   (`site-apis.mjs` `fill`). Cause: parameters were substituted first and the
   result rescanned for secrets. Since A30-8 the json and header escapes keep
   braces. Fix: one pass over the owner's template, so each `{{…}}` is a
   parameter or a secret and a substituted value is never rescanned. Guard
   `test/site-apis-secret-rescan.test.mjs` (json, header and url escapes);
   3 of 5 cases red before. Sweep 4/4.
2. **A part's users were found by one spelling** (`builder/publish-pages.mjs`
   `salvagePlan`). Only `"@/routes/-parts/<name>"` counted. Fix: a regex
   accepts `@/routes/-parts/` and `./-parts/`, single and double quotes,
   with or without `.tsx`. A part a live page uses is kept. A part the home
   page uses refuses, as a failed home page does. Two A22-4 tests used
   index.tsx as the importer, so they now use another page (dated comments).
   Sweep 4/4.
3. **noOverlap accepted REAL/NUMERIC columns** (`builder/site-rules.mjs`).
   `num` lists every numeric type, and `"number"` maps to REAL, but the
   constraint uses int4range. Fix: the schema engine now records its integer
   columns as `int` beside `num` (`site-schema.mjs`). The rules reader counts
   a stored column as an integer only when `int` lists it, and a declared
   type only when it is an integer type. A stored table without `int`
   (written before this change) is refused rather than guessed. The A29-5
   fixture gains `int`. Sweep 4/4.
4. **A held replacement could be held twice** (`worker.js`, the media
   route). If the seal landed but the paired mark's put failed (swallowed by
   `.catch`), the next sighting sealed again. Fix: the hold's id is written
   to the `replacing/` record before the seal. Every record write that fails
   answers 503 (retry). A later sighting proves the seal from the draft's own
   revisions (`savedRevision`) and writes only the mark. **The records no
   longer pile up**: after Publish marks a revision applied,
   `dropReplacingRecords` removes every record paired at or below it, and any
   unpaired record older than twice `MEDIA_DRAFT_MS`. Site deletion already
   clears the rest (`clearSiteDraft`). Guard MR4d in
   `test/media-reliable.test.mjs`. Sweep 4/4.
5. **A cut render check kept landmarks of removed routes** (`worker.js`
   `saveLandmarks`). Fix: callers pass the routes the publish has
   (`landmarkRoutes(pages)`: the edit spine's pages, and the build path's
   from its publish callback). Old marks are kept only for routes in that
   set; when the set is not told, none are kept. A22-5's test now has a
   `/menu` page and a `/gone` mark. `site-busy`'s landmark is re-anchored.
   Sweep 3/4: the survivor is the branch for routes not being told, which no
   driven path reaches.
