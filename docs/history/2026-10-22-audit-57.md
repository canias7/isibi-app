# Audit finding 57: A32-1 (2026-10-22)

From `docs/audits/2026-10-17-builder-audit.md`, on branch `audit-57` (from `codex-work-into-claude` `fdf73825a`). Offline; nothing spent, nothing deployed.

## Re-verified against the current code: real

- `translatePages` (`builder/site-translate.mjs`) wrote every translation through `applyEdits` (`builder/site-text.mjs`), which refuses a replacement containing `" ' \` { } < > \` or longer than 400 characters. One refused edit refused the whole batch, across every page.
- The pages then came back in the primary wording with `failed: true`. Neither caller (the spine's `filesFor` and the build path's loop in `worker.js`) read `failed`, so the language was published in English under its prefix.
- The round itself was marked `ok: true` and its usage was charged. `nextCache` stored the refused translation, so every later publish found nothing missing and never asked again.
- Red reproduction: the new cases (below) fail on the old code. The unit file fails 8 of 9 with stub exports added to the old module. The two driven cases fail 2 of 2.

## Fix

- **`usableTranslation(from, to)`** (`site-translate.mjs`): straight quotes become typographic ones (’ “ ”), and line breaks become spaces. These are safe in JSX text, in a quoted attribute and in a JavaScript string alike, so no context-specific escaping is needed. A brace, angle bracket, backtick or backslash left after that, an empty answer or one over 400 characters gets `null`. An answer identical to the original is kept as it is.
- **`translatePages`** applies one edit at a time, back to front. A refused string keeps its original wording and is listed in `refused`, and the rest of the language is written. `failed` now means "at least one string refused".
- **`nextCache`** never stores a translation that `usableTranslation` refuses (the string stays missing, so it is asked again). It stores the usable form, so a cache holding a plain apostrophe from before this fix heals.
- **Billing** (`worker.js`, spine and build path): only a round with something usable hands its usage back. A refused answer (wrong length or shape) or an all-unusable one is not charged. On the spine, an all-unusable answer is `ok: false, why: "unusable"`, and a partly usable one carries `kept: n`.
- **Telling the customer**: the spine adds `langNote(langOutcomes)` to `renderNote`, which every edit and add-on reply already shows (`renderTail`). It says, for example: "The es pages could not be translated this time, so they show your original wording for now; I'll try again on your next change." **Not done for a first build's reply**: the build path has no per-language outcome. It is recorded with A32-4.
- **Not in scope**: A32-2 (batching large translations, `stop_reason`), A32-3, A32-4 and A32-5.
