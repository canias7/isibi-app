- **The router** was told "One change happens per turn", so run 52's Visit move
  went into `alsoAsked` although the look rung can make both changes.
- **The routing reply** carried `alsoAsked` as a note; nothing branched on it.
- **The browser** posted the whole message to the edit route.
- **The picker** was shown the whole message, so it picked `shape` for the

- **The steps**: every page lane went to one page (`fallbackPage`: the

  `shape` step was handed the home page and both halves' words.
- **The reply** said both "⚠️ I read the / page and couldn't find a change…"

## The fix

**1. The router puts off only what its answer cannot do this turn.**
`alsoAsked` is now "a second request this turn cannot carry out": something
to add beside a change, a change beside an addition, or a `data` or `text`
change beside a change of another kind. Several changes the look rung can make
are one `look` answer, and a `look` answer naming changes on more than one
page, or on the whole site and a page, leaves `page` out. The words it copies
are held back, so the description says so.

**2. A part put off is held back, never run.**
- The browser posts `alsoAsked` with the message, on both `siteEdit` and
  `siteAddon`, and a queued job replays the body whole. The resume record
  keeps it too (`also`), so a hop from a watch resumed after a refresh holds
  back the same words. The edit canary posts it exactly as the browser does.
- The edit and add-on routes take those words out of the message before the
  picker, any lane or any writer sees it (`heldBack` in
  `builder/site-ask.mjs`), and answer with `deferred`: the words really held
  back, in the customer's own spelling.
- The reply's last sentence ("I only did one thing this time. Say “…” and
  I’ll do that next.") is composed from the route's `deferred`, not from the
  routing answer, so it says only what the route really held back.
- Words the route cannot find in the message are refused at no cost, before
  anything runs (`route/held-unread`, an `explain` and ours; the add-on's
  `held-unread`). Running the whole message would also run the part promised
  for later.
- `readAlso` no longer cuts the copy at 200 characters. A copy cut between two
  words is still found, so only its start would have been held back and the
  rest would have run. A copy longer than any message (2,000) is dropped, and
  the screen still shows at most 200 characters of it.

**3. Each change runs with its own page and words.**
- The picker answers `scopes`: one entry per separate change, with its
  `part`, its `words` copied exactly from the message and, for a change on one
  page, its `page`.
- `readScopes` in `builder/site-lanes.mjs` keeps an entry only for a part the
  answer picked. It spells the page the way pages are compared, and keeps the
  words only when they are really in the message (`wordsIn`: case, spacing and
  curly quotes forgiven, on word boundaries). A `String(["…"])` coercion is
  refused.
- In the look door, a page lane runs one step per page it was scoped to,
  handed only that change's words. An own lane (description, colours, fonts
  and the rest) is handed only its own words (`asks`). Two scoped changes on
  one page are one writer handed both sets of words (`mergePageSteps`), and
  two page steps with different words are two operations
  (`samePageOperation`).
- A scoped page the site does not have is said before anything runs
  (`page/no-page`). **Changed the same day**: it now withholds only that
  change, and the rest of the message runs.
- A lane with no scope, or words the message does not hold, runs exactly as
  before: on the whole message, on the router's page or the home page.
  **Superseded the same day** (the correction below): that fallback is what
  the owner's review reproduced. Only an answer with no scope metadata at all
  runs that way now; on a scoped answer such a lane is withheld.
- The removal door's picker scopes the work beside the routed change the same
  way. The router's own step still reads the message, as it did.

Not done, by design: no keyword matching; the words are the customer's own,
found in the message, or they are not used. Visit is not assigned to the
whole request. The router sentence was rewritten to the route's real
capability, not deleted.

## The correction after the owner's review (2026-09-29)

Owner: *"The valid-scope cases pass independently: 21/21 focused tests. Two
route-level reproductions still undermine the scope guarantee. 1. With Run
52's request and a shape scope containing page: ["/visit"], readScopes
converts the invalid target to "". The route calls the index.tsx writer with
the Visit-only instruction. 2. With page: "/visit" and words: "Move that
section up"—which does not occur in the request—readScopes returns words: "".
The route then hands the Visit writer the entire original request, including
the site-wide description change. Distinguish absent legacy scope from
explicitly invalid scope. Once an operation supplies scope metadata, failed
validation must not widen its instruction to the whole request or redirect it
to the homepage. Reject or withhold the affected operation with an accurate
outcome. Preserve independently valid work where the existing partial-success
contract allows it. Keep the ordinary single-change compatibility cases

**Both reproduced first**, through the real route at `2b7eeca3`: the
`index.tsx` writer was handed the Visit words (it found nothing, climbed to
the full page writer and the screen said "The builder is busy"), and the
`visit.tsx` writer was handed the whole request and moved the band, while the
screen named only the description.

**What changed:**
- **`readScopes` answers `{ scoped, ops }`.** `scoped` is false only when the
  answer carries no scope metadata at all (`scopes` absent, `null` or `[]`):
  the legacy shape, run exactly as before. Otherwise every entry naming a
  picked lane is an op, and one that fails a check is marked `invalid`
  ("page" for a page that is not a path, including a non-string; "words"
  for a copy that is not a string or not in the message), never blanked.
  Nothing is capped or dropped in silence.
- **The route withholds, never widens or redirects.** On a scoped answer an
  invalid op, an op aimed at a page the site does not have, and a picked lane
  the answer left without any scope each become a withheld step: no model
  call, no charge, and its own sentence (`picker/scope-unread`, an `explain`
  and ours; a missing page keeps `page/no-page` and names the site's pages).
  The valid ops still run on their own pages with their own words, and the
  withheld ones reach the reply through the existing `partial` contract. A
  message whose every change is withheld answers that sentence at no cost.
- **A missing page no longer takes the whole message down**: it withholds
  that one change, and the description beside it ships (it refused the whole
  message before anything ran).
- **Scoped and unscoped page steps never merge**: the merge used to hand the
  scoped change the whole message (`joinAsks`' old fallback). A withheld step
  is never a sentence page step, so nothing joins it and no success retires
  its sentence.
- **The QR placement follows the lane that runs**, not the pick.
