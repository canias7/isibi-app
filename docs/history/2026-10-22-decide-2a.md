# Decision 2a — the spam check on declared write functions, 2026-10-22

Branch `decide-2a`, from `origin/combine-groups` (`36671236e`). Offline only:
nothing paid, no model call, no live write. Follows audit G6
(`docs/history/2026-10-22-audit-g6.md`), where the owner chose option A.

## What changed

- **The field.** A declared function may carry `writes: true`
  (`FUNCTION_ITEM` in `builder/site-table.mjs`, shared by the build's
  `design_schema` tool and the add-on's function step). The designer is told to
  set it when the function inserts, updates or deletes rows, and that a page
  calls such a function with `useRpcAction` / `useCancelClaim` /
  `useAmendClaim`.
- **Carried end to end.** `cleanAdd("function")` keeps `writes: true`, keeps an
  absent key absent and refuses a non-boolean (`bad-writes`, with its own
  customer sentence, like `bad-internal`); `foldAdds` and `mergeAddonSchema`
  carry whole objects; `normalizeSchema` and the `_meta.functions` record in
  `applySiteSchema` (`site-schema.mjs`) keep it (absent stays absent);
  `TOOL_FIELDS.function` names it.
- **The gate.** `rpcGate` / `rpcName` / `rpcWrites` (`site-turnstile.mjs`);
  `turnstileGate` (`worker.js`) asks it first. For `rpc/<fn>`: the token field
  is stripped from a one-object body; no secret → passes, with no schema read;
  a function not declared `writes === true` (reads, every older function) →
  passes; a declared write → the token is required and verified exactly as an
  insert's (a missing token, or a body that is not one JSON object, is
  refused; an unreachable Cloudflare fails open as inserts do). Case and
  trailing slashes in the path do not bypass it.
- **The kit** (`rows.ts`). `useRpcAction`, `useCancelClaim` and `useAmendClaim`
  attach the token with `challenged()` and reset it afterwards, as
  `useCreateRow` does. The widget is mounted site-wide at the root
  (`SpamGuard`), so a claim link's page has it too; the claim token still proves
  who, this proves a person. `useRpc` and `useClaimedRow` (reads) send none.
  The amend body still writes `tok` last.

## Tests

`test/rpc-writes-turnstile.test.mjs`, 11 cases: a write without a token refused
(also empty body, odd case/slash); a valid token passes and is stripped; a
rejected token refused; a read, an undeclared name and a non-boolean `writes`
pass; Turnstile off passes with no schema read; the tool, cleaner, fold, merge,
engine and the real `applySiteSchema`'s `_meta` write (fetch seam) all keep the
field; the worker wiring and the kit hooks.

- **Red check**: on the old code all 11 fail.
- **Sweep**: 6 mutants, all killed (rpcWrites ignoring the field; the secret
  check removed — first survived, since `verify` passes with no secret, killed
  after asserting no schema read when off; `_meta` dropping it; the cleaner
  dropping it; the engine dropping it; `useRpcAction` sending no token); the
  comment-only control survived.
- **Affected files**: turnstile, one-row, addon-steps, dropped-fields,
  site-functions, site-idem, schema-column-union, addon-route: 338 / 338.
- **Full suite** (local, node_modules linked): `11968 / 11961 / 4 / 3`. The 4
  failures are not this change: `no-generated-deps`'s node_modules case fails
  because of the linked node_modules (the same on the old code); the media
  browser-mode, composer and purchase-recovery cases pass when their files are
  run alone, on both trees (load timing).

## Left

- Existing sites' functions carry no mark until the builder next designs them,
  so they stay ungated, as before. No backfill was made.
- A page that calls a `writes` function through `useRpc` (the read hook) would
  be refused on a protected site; the tool description steers away from it, and
  no lint enforces it.
