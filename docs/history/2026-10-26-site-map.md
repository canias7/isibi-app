# 2026-10-26 — the one site map (branch `site-map`, from `fix-run6` `065eb26bd`; not merged, not deployed)

The owner's decision: one map of the site that every step reads, so every step
"knows everything". The start was the router's `siteMap()` in
`builder/route-inventory.mjs` (backlog: "One site map that every step reads").

## What changed

- **`builder/site-map.mjs`** (new). `buildSiteMap({ pages, parts, spec, label, css, version })`
  builds one structured map from the stored source and the live schema. It is deterministic and makes no model call:
  pages (route, file, title, headings, kit sections, parts, form, reads/writes),
  parts (file, the routes that render each one, and whether it is shared), **key text facts**
  (email, phone, opening hours, prices, addresses, each with every file and route
  it is written in, `shared`, `everyPage`), tables (columns with type, required,
  default; access; rules), page↔table links, the frame (the menu editor's own
  readers), theme tokens and fonts, and photos. A part that could not be read is `null`, never an empty list.
  `mapFor(kind, map)` gives each step its slice: `router`, `text`, `addon` (the facts index with locations,
  budgeted 1,800 / 2,400 chars), `row` (required columns per table), `frame`
  (frame plus the tables visitors write), `reply` (what exists), `diagnose` (compacted).
- **Saved per version.** `refreshSiteMap` writes `source/<slug>/sitemap.json` and
  `source/<slug>/sitemaps/<version>.json`. It runs after every save in
  `recompileAndPublish` (every edit, add-on, publish, page removal and rename) and after a published build.
  `restoreVersion` puts back the restored version's map (`restoreSiteMap`), or rebuilds it for a version older than the map.
- **Always current** (the owner's emphasis, mid-task). Several change paths never publish:
  schema and access changes, Data-panel edits, discard draft, draft saves under draft-first, and uploads.
  So no reader takes the saved copy on trust. `currentSiteMap` rebuilds the map from the source and live schema
  on every read. Only when that rebuild fails is the saved copy served, and then it is marked
  `stale: true`. The other readers (router, converse, add-on) build from what their own request just read.
- **The landmarks save bug.** The build path's `saveLandmarks` was gated on `out.ok`, which
  `publishPages` never returns on success, so no first build ever saved its landmark map. It now reads
  `out.page === "app"`, as the layout save does. Three older guards were updated to the new gate.
- **Router.** `routeInventory` takes `parts` and adds the key facts with where each is written.
  The facts' room comes out of the same `INVENTORY_CHARS` budget; they are added after the stable prefix,
  so caching is unchanged. They are left out for a request part (`words: false`).
  `routeDigest` also reads the site's parts, bounded.
  Up-front questions use the router's existing ask. No new rule text was added: the facts are what let it notice.
- **Text step.** (1) A step scoped to a page is also shown the parts that page renders
  (`scopedText(items, scope, pages)`, followed through nested parts), so a footer part's
  hours are on /contact. (2) A scoped no-match whose message holds the site's own words
  from a page or part it was not shown is asked once more with every page, and the edit is applied there
  (`quotedElsewhere`: the site's words found literally in the message, not a keyword list).
- **Add-on.** `siteFacts` adds `keyFacts` (the map slice from the pages and parts it is shown), and
  `siteNote` prints it as facts. Behaviour is otherwise unchanged.
- **Conversation.** `readConverseContext` adds `keyFacts`, and `converseContext` prints it.
- **Diagnosis.** `list_site` returns `map` (the current map, compacted).
- **Not rewired**: the row designer's and the frame writer's own live readers already read the live schema.
  The `row` and `frame` slices exist but are not yet their input.
- `Dockerfile`: `builder/site-map.mjs` added to the worker tree (the job runner imports it), so **the image rolls**.

## Round 2 (same day, the coordinator's follow-up: the map reaches every step)

- **Row designer**: `siteFacts.rowNote` = `mapFor("rowNote")` (each table's columns, `*` for one an
  entry must fill, who may write it), passed only to the `row` designer (`noteFor`) and printed by
  `siteNote`. The live required-columns read (`aRowRequired`) stays the truth.
- **Frame writer**: `runFrameEdit`'s existing `note` carries `mapFor("frame")` (the frame now, the
  tables a page writes to, the key facts with locations), beside the live `frameTablesOf` tables.
- **Reply model**: `composeModelReply` reads the current map (`currentSiteMap`, bounded 2.5 s,
  failing open) and `replyContext` prints its `reply` slice (pages with titles, tables, frame) as facts.
- **Up-front questions**: no rule text. With supplied answers, the first routing of "make the cafe
  opening hours 8am to 4pm" is shown `hours "Open Mon–Sun 9am–5pm" in part footer (on every page)`,
  is offered the existing question, and its `clarify` comes back as the answer with nothing else run.
  A part is not offered a question, and a stray clarify is turned into work by `partClarifyChoice`.
  Whether a real router asks here is a live measurement, not made.
- **Router slice size** (chars/4): on a realistic site (8 pages with a 24-item price list each, a footer
  of hours, phone and email, 12 tables of 8 columns), the facts slice is 1,216 chars (~304 tokens) and the whole
  inventory with facts 2,102 chars (~526 tokens). The ceiling is the shared 6,000-char budget (~1.5k tokens).
- Tests: `test/site-map-steps.test.mjs`, 6 cases; the guard's reader list now includes `frame`, `reply`,
  `rowNote`. Sweep: 7 of 7 killed, the comment-only control survived. Full suite `12856 / 12851 / 2 / 3`.
  The two failures (`canary-reopen-browser` REOPEN 1, `no-generated-deps` symlink) each pass alone
  (2 / 2, and the second once the worktree's `node_modules` link is removed).
