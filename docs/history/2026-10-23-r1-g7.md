## Fixed

**A19-2: the `spots` decor's dots.** `dot(h, x, y, r, A)` was called with four
arguments, so every layer read `circle at 31px 47px 6px`, with unitless stops and
`/ NaN` in dark mode. One bad layer drops the whole `background-image` list
(13 themes, 4 of them on the shortlist). The fix passes x and y separately
(`builder/site-theme.mjs`). Test: the decor loop in `test/site-theme.test.mjs`
now refuses NaN or undefined, an `at` that is not two lengths, and a unitless
non-zero stop. Red on the old file (1 of 54). Sweep: 4 mutants, 3 killed. The
fourth replaced dark mode's `A * 0.9` with `undefined`, which emits a valid
opaque colour, so it is equivalent. The control survived.

**A19-3: a render check that was cut short proves no rule dead.**
`renderReport` (`builder/site-render.mjs`) no longer carries `deadSelectors`
when `cut` is set. The spine's gate (`worker.js`) also ignores them when
`render.partial` is true, which covers a container on the previous image. Tests:
`test/build-repair.test.mjs` (a cut report carries none; a whole report keeps
them) and two route cases in `test/edit-failure-paths.test.mjs` (sync and job:
a partial check publishes once, with no correction round). Red: 3 fail on the old
files. Sweep: 3 worker mutants and 2 render mutants, all killed; both controls
survived.

**A19-4: the kit closure follows relative imports.** The new `relativeSpecs`
(`builder/kit-closure.mjs`) resolves a kit file's `./` and `../` imports against
its own directory and keeps only paths under `src/`. A seed page's relative
imports are not followed, because those are the site's own `-parts`. Tests
(`test/kit-closure.test.mjs`): a driven case (`_ink`, a `../` climb, a climb out
of `src/` that is dropped, a seed's `./-parts` ignored), and the real template:
`actuarial.tsx` now brings `_ink.ts`. Red: 2 fail. Sweep: 4 mutants, all killed.
A fifth, a guard on the importer's own path, survived because every caller passes
an `src/` path, so the guard was removed as dead. The control survived. No new
module; `kit-closure.mjs` is already in the Dockerfile.

**A20-4: font names keep the most specific family** (`builder/site-fonts.mjs`,
`matchFontName`).
- The distance step no longer lands on a cut of a family (`-sc`, `-kr`, `-jp`,
  `-tc`, `-hk`, `-ar`, `-he`, `-th`) unless the query names the same cut.
- The forward prefix ("noto" → a completion) is unchanged.
- The reverse prefix (a family that prefixes the query) now counts only when
  what is left is one commercial suffix (`pro`, `std`, `lt`, `mt`, `next`).
  Exactly one family can satisfy that, so no sort is needed.
- The audit's probes now answer: Merriweather Sans Pro → `merriweather-sans`,
  Roboto Slab Pro → `roboto-slab`, Sofia Sans Pro → `sofia-sans`, Playfair
  Display Pro → `playfair-display`, IBM Plex Sans Pro → `ibm-plex-sans`.
- **Kept limits:**
  - "Sofia Pro" still answers `sofia`, because `sofia` + `pro` is exactly the
    shape the rule accepts.
  - A non-exact match still adds no "used X for Y" note to the reply. That needs
    a field from `resolveFont` through `fontsIn` to `readCss`, which is not done
    here.
- Test: `test/site-fonts.test.mjs`. Red: 1 fails. Sweep: 4 mutants killed; the
  control survived. All 9 other font and CSS test files pass.

**A20-5: the Fontsource fetch's success path is driven.** The harness behind
`test/edit-failure-paths.test.mjs` takes an optional `fonts` stub. A sync CSS
edit naming "Be Vietnam Pro" gets a Fontsource-shaped answer (weights 700 and
400, subsets latin and vietnamese). The test asserts the API is called, then the
regular latin woff2, and that the build's `fontFiles` carries exactly those
bytes in base64. Sweep over `fetchSiteFonts`: 4 of 5 mutants killed. The one that
survived checks `url.woff` instead of `url.woff2` in the guard; it is equivalent
under this fixture, which supplies both. The control survived. **Not done:** the
render-check probe of `document.fonts` (a container change).

**A21-3: a rewrite too large to show.**
- Before: over `MAX_PRIOR_CHARS` the revise prompt listed page names only and
  said "write them again in full", and every returned page replaced its stored
  one.
- Now `priorPagesBlock` shows `reviseSent`'s selection: `priorPagesSent` with no
  `keep`, and without the add-on's at-least-one fallback, so one huge page is
  never inlined. It names the rest as unseen and not to be returned.
- `publishPages` reads the same selection, drops any returned page the writer
  was not shown (the stored page stands), and records the drop as
  `unseenDropped`. **That field is not told in the reply yet.**
- Revise never takes the band fan-out (`planRefusal` answers `revise`), so every
  revise prompt comes through this block.
- Tests (`test/revise-keeps-pages.test.mjs`): the prompt over the window, a
  blind page kept while a shown page is taken, and a control under the window.
  Red: 2 fail. Sweep: 3 mutants over `page-gen.mjs`, 2 over `publish-pages.mjs`,
  all killed between `page-gen.test.mjs` and `revise-keeps-pages.test.mjs`;
  controls survived. The existing "too large to show" case in
  `test/page-gen.test.mjs` still passes. It is the one-huge-page path, which is
  what made the fallback cut necessary.

**A21-4: the page's own components fill the writer's budget first.**
- `partsSent` takes `first`. The named components are selected first, then the
  rest fill what is left. `shown` and `names` stay in stored order.
- The page rung passes the target page's own `-parts` imports. It passes them
  both to its own `partsSent` and, through the new `partsFirst`, to
  `briefWithLayout`, which builds the prompt from a second `partsSent` call. The
  first try missed that second call, and the route test caught it.
- Tests (`test/edit-page-context.test.mjs`):
  - a route case where three band-sized parts are stored first: the card the page
    renders is now in the prompt, and nothing is reported "too long";
  - a unit case for `first`.
- Red: 2 fail. Sweep: 4 `page-gen` mutants and 2 worker mutants, all killed;
  both controls survived.
- **Not changed:**
  - When a page's own components really do exceed the budget, the refusal still
    says "too long to show the builder in one go".
  - In the route case the card's rewrite is then held by the text-loss guard
    (`partsLossHeld`), which is separate from this finding and was not touched.

## Needs the owner's decision

**A19-5: the Download's `src/styles.css` is only the site's own CSS layer.**
1. Have the container return its final composed `src/styles.css` with the kit
   closure, and store it beside `kit.json`. Exact, but it changes the
   container's answer and rolls the image.
2. Compose it in the Worker: the base, then `themeCss` of the look, then the
   site's CSS. No image roll, but it copies the container's composition (fonts,
   guards) and can drift from it.
3. Ship the template's base `styles.css` and put the site's layer at its own path
   with an `@import`. The download builds with Tailwind but without the theme.
   Cheapest.

Recommendation: 1.

**A20-3: a fetched face is one static 400 latin file declared 100–900.**
1. Declare the fetched file at its real weight. The browser then synthesises
   bold instead of drawing every weight as regular. Small, but needs the weight
   carried with the bytes.
2. Fetch 400 and 700, plus the subsets the site's languages need, one
   `@font-face` each with its `unicode-range`. Better type, but the request to
   the container grows with each face (about 20–60 KB of base64 each, against
   the 2 MB per-file bound).
3. Prefer the variable file where Fontsource has one.

Recommendation: 1 now, then 2 for non-Latin sites.

**A32-2: a translation that cannot fit or finish fails the same way on every
publish, and is billed.**
1. Batch the missing strings, read `stop_reason`, keep each batch's successes,
   and charge nothing for a refused round.
2. Also remember a deterministic failure (size or shape) and stop re-asking
   until the strings change.
3. Also move translation out of the publish turn under `PARALLEL_WRITES`.

These are a billing rule and a timing change. Recommendation: 1 and 2 together.

**A32-3: translated pages cannot be edited.**
1. Recognise a language prefix in `page/no-page` and `text/no-match`, and say
   that translated wording is produced from the primary language. Cheap and
   honest.
2. Add an edit that overrides one cached translation
   (`langStrings[tag][english]`) and republishes. This is a new edit kind.

Recommendation: 1 first.

**A32-5:** parked by the owner. The options in the audit stand: parse the TSX,
or drop code-shaped spans before `collectStrings`.
