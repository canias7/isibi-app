## A16-5 — the SSRF guard checked hostname strings only (fixed)

- **Fix, part 1**: `site-ssrf.mjs` gains `resolvesBlocked(host, resolve)`.
  - When a resolver exists, every address the name resolves to is checked.
  - Any blocked address, no address, or a failed lookup counts as blocked.
  - IP literals keep the string check.
- **Fix, part 2**: `ipv4Blocked` also blocks 192.0.0.0/24, 198.18.0.0/15, 224.0.0.0/4 and 240.0.0.0/4.
- **Fix, part 3**: `safeFetch` (`worker.js`) asks `resolvesBlocked(u.hostname, globalThis.__SITE_RESOLVE_HOST)` on every hop.
- **Fix, part 4**: the container's `installGatewayFetch` (`builder/container-job.mjs`) installs that resolver (`node:dns/promises` `lookup`, all addresses) and removes it on restore. The Worker has no resolver, and its runtime cannot reach private ranges, so nothing changes there.
- **Tests**:
  - `test/safe-fetch-redirects.test.mjs`: names resolving to loopback, metadata or benchmark addresses, or not at all, are never fetched, on the first hop or after a redirect; a public name is read as before. There are unit cases for `resolvesBlocked` and for the new ranges.
  - `test/sb-gateway.test.mjs`: the resolver is installed and restored.
- **Red check**: with the old `worker.js` and `container-job.mjs`, 2 cases fail.
- **Sweep**: 6 of 6 killed; the control survived.
- **Limit kept**: Node's fetch resolves the name again, so DNS rebinding between the check and the connect is not closed. Closing it needs connection pinning (an undici dispatcher, which is not installed) or an egress proxy, and choosing one is the owner's call.

## A28-6 — held starter rows counted every row as seeded (fixed in part)

## Needs the owner's decision

- **A16-4: a job can write another site's alias row.**
  - The gateway binds only `slug` and `uid` on `site_aliases` POST.
  - Even a plain insert of a never-used alias, equal to another site's name, takes that site's address.
  - The rename path in a container job legitimately writes alias rows with merge-duplicates, so simply dropping POST would break renames.
  - **Options**:
    - (a) Move alias writes to a Worker-side RPC that refuses an alias owned by another account, or equal to another site's slug. This is the safest option and is my recommendation.
    - (b) Have the gateway read the existing alias row and the slug's owner before forwarding a POST.
    - (c) Refuse `on_conflict` and merging `prefer` on gateway writes only. This closes the overwrite, but not the insert hijack.
- **A16-7: the diagnostic routes are open to any signed-in account.**
  - The routes are `/api/_slow`, `/api/_hold`, `/api/_egress` and `POST /api/site/job-probe`.
  - The owner's wall-probe and job-probe workflows use them.
  - **Options**:
    - (a) An operator allowlist of user ids in a new env value. This is my recommendation. It needs the value set on deploy, and while the value is empty every request is refused.
    - (b) A dispatch-only secret header, like the paid workflows use.
    - (c) A `useQuota` bucket on each route, with `mb` capped below the isolate's limit. This weakens the memory probe's purpose.
- **A29-9: an access widening is applied on the model's word alone.**
  - The vague reply wording is held for the model-written replies work, by the owner's rule.
  - **Options**:
    - (a) When read widens to public or members on a table whose read is none or own, ask a question back unless the instruction says to open it. This is my recommendation.
    - (b) State the new level in the reply now ("anyone can now read bookings"), which reopens the reply wording.
    - (c) Leave it until the model-written replies work.
