# Audit finding 53 — one row per protected submission (A30-2), 2026-10-22

Branch `audit-53`, from `codex-work-into-claude` (`fdf73825a`). Offline; nothing spent, no live data, not merged or deployed.

## Re-verified on today's code

- `turnstileGate` (`worker.js`) still began `try { body = JSON.parse(sent || "null"); } catch { return {}; }` and `if (!body || typeof body !== "object" || Array.isArray(body)) return {};`: a non-JSON body or an array passed with no refusal, before the secret or the table was asked. The proxy then forwarded the original bytes (`gate.sent` undefined). So on a `collect` table with Turnstile on, `[{...}, …]` with no token reached PostgREST as a bulk insert. `site-row-effects.mjs` (today's work) runs after the insert and does not change this. Real.

## Fix

- `site-turnstile.mjs`: new `oneRow(sent, contentType)` answers `{ row }` only for one JSON object sent as `application/json` (charset allowed); otherwise `{ bad }` (`content-type`, `not-json`, `array`, `not-object`).
- `worker.js` `turnstileGate`: reads the shape first. When it is not one row: no secret → `{}` (unchanged); table not `collect` or schema unreadable → `{}` (unchanged); a protected `collect` table → refused 403 "Please send one submission at a time.", before the token is judged. One-object bodies take the old path exactly.
- Not changed (kept separate): `data/rpc/<fn>` writes still skip the gate (the table read off the path is `rpc`); the per-request data limiter; the idempotency findings A30-4/A30-5. One small difference: on an unprotected table, a JSON object sent with a non-JSON content-type is no longer token-stripped (PostgREST would not have taken it as JSON anyway).
