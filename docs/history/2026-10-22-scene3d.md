# 2026-10-22 — Scene3D: a ready-made 3D component in the kit

The owner: *"do the 3d thing really quick"* — step 1 of the earlier plan: a
kit component the page writer drops in when 3D genuinely fits the business,
instead of hand-writing three.js each time. Offline; no model call, no paid
run, not merged or deployed.

## What changed

- **`builder/lovable/template/src/components/ui/scene-3d.tsx`** — `Scene3D`:
  - props: `label` (required, read out as the picture's description), `shape`
    (`box | sphere | torus | knot | cone | cylinder`, default `knot`), `src`
    (a glTF/GLB url, e.g. an uploaded model; it is centred and scaled to fit),
    `poster`, `height` (px, default 360, fixed), `autoRotate` (default on),
    `caption`;
  - **the poster is what renders**: on the server, before load, when WebGL
    does not start, and for reduced motion. With no `poster` it is a quiet
    placeholder (a faint box icon on `bg-muted`). Server markup and the first
    client render are the same, so hydration is clean;
  - three.js (and the glTF loader) are dynamic `import()`s inside an effect,
    started only once the box is within 200px of the screen; never in the
    server render or the first download. It uses `three` directly, not
    `@react-three/fiber`, for one object;
  - reduced motion: the poster and a "View in 3D" button; once opted in it
    does not spin by itself;
  - drag to turn; arrow keys turn it when focused; a "Reset the view" button.
    The buttons sit beside the `role="img"` stage, not inside it (a picture
    hides its children from assistive technology);
  - colours from the theme only: a primitive is painted with `--primary`
    (resolved by the browser, so oklch works), against the box's `bg-muted`.
    A GLB keeps its own materials.
- **Registered**: `builder/ui-components.mjs` (`scene-3d`), and regenerated
  with the repo's own generators: `builder/component-api.mjs`
  (`node builder/gen-component-api.mjs`; 2,042 signatures) and
  `docs/components.md` (`node builder/gen-components-doc.mjs`).
- **`builder/page-gen.mjs`**:
  - PAGE_RULES' 3D paragraph keeps "ALMOST NEVER RIGHT", "ONLY where the design
    step asked for it" and "never words, a logo or a background in a canvas",
    and now says: when it did, use `Scene3D` rather than a raw `<Canvas>`;
    a raw Canvas only for what Scene3D cannot show;
  - `sceneDirective` (the brief line when the design asked for a scene) points
    at `Scene3D` the same way (it still names `@react-three/fiber` for the rare
    case, which `site-marks`' hop-3 guard reads);
  - `sceneOn` (does this page really draw the scene?) also counts a `Scene3D`:
    its import AND its element, never either alone. Without this a page using
    the component would have read its designed scene as `unverified`.
- **Test**: `test/scene-3d.test.mjs`, 7 cases: the signature and registration;
  three.js only by dynamic import inside an effect, no static import and no
  fiber; the poster-first states (reduced motion, WebGL probe, failure,
  opt-in, no spin when reduced); accessibility (labelled picture, hidden
  canvas, arrow keys, fixed height, no button inside the picture); no literal
  colour; `sceneOn` with Scene3D (and dead import, element alone, a prefix);
  the prompts.

## Readings

- **Typecheck**: the component compiles under `tsc --strict` with
  `@types/three@0.180.0` and `@types/react@19` (a scratch project; rc 0).
- **Render, headless Chromium 1194**: the page was server-rendered with
  `renderToString`, then hydrated in the browser, three ways:
  - WebGL on (`--use-angle=swiftshader`): the canvas started, no console error
    and no recoverable (hydration) error, stage height 360;
  - WebGL off (`--disable-webgl --disable-3d-apis`): the poster stayed, no
    error, height 360;
  - reduced motion: the poster and "View in 3D", no canvas, no error.
  Screenshots (scratchpad): `scene3d.png`, `scene3d-fallback.png`,
  `scene3d-reduced.png`.
- **Kit integration checks** (`kit-render`, `kit-a11y`, `kit-effects`,
  `kit-paint`) **not run here**: the template's `node_modules` are not
  installed in this checkout and the disk is tight. They run in the `site
  build` workflow (dispatch, or a feature-branch push touching their paths).
- Focused files (scene-3d, component-api, components-doc, site-marks,
  page-charts, wiring, site-plan, template-deps, page-gen): 412 / 412.
- Full suite: see the owner-notes entry.

## Rollout

- Not merged, not deployed. Not live-tested with a model; whether the page
  writer reaches for it is unmeasured.
- Follow-ups not done: an uploaded `.glb` reaching the page writer as a `src`
