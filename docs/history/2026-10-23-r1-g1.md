## A07-4 — a version staged with no script was saved as the draft

- **Real.** `stageBuild` stages `worker: null` when the container packages no
  script. Live, `activateBuild` undoes the activation (`not-served`). Under
  draft-first, `saveAsDraft` recorded the version and ran `commit` (billed),
  the preview could never go up, and Publish later refused the revision.
- **Fix** (`worker.js`). After a successful stage, under draft-first, a
  version with no script is refused before the publish gate:
  `{ ok: false, error: "no-script", ours: true }`, refunded, nothing saved.
  `compileMsg` says "the new version was built, but its server part couldn't
  be packaged, so nothing was saved. This is on us". The Build's stage dep
  throws the same way (our failure, uncharged).
- **Left:** `convergePreview` and `repreviewVersion` still retry whatever the
  error (the audit's second half). With the save refused, the `pack` failure
  no longer reaches them; an old draft whose version has no script can still.
- **Tests:** `test/draft-outcome.test.mjs` DOR3b (the real request flow with
  the compiler stub's `worker: false`: no revision of the job, the draft
  record unchanged, not billed, refunded in full, the sentence, live
  unchanged) and DOR3c (the Build path's refusal, between its stage and
  activation landmarks). **Red:** DOR3b fails on `main`'s `worker.js`.

## A14-2 — a try lost to its own request's overlap showed "Send it again"

- **Real.** `shownRun` (`builder/request.mjs`) excluded hop, climb,
  answerless and held-retry, not `overlap`, so `requestView` listed the lost
  try under its part and the page rendered its reply ("… Send it again.")

- **Fix.** `overlap` joins the exclusions. The re-run carries the same
  `routedCost` (from the part's route), so the routing charge is still said.
- **Tests:** CW5 (`test/concurrent-writes.test.mjs`) now asserts
  `requestView(rec).parts[0].jobs` is the second try alone. **Red:** fails

## A14-3 — page removal, move and photo facts in the live tense under a draft

- **Real.** `pageOpFacts` and `outcomeFacts` (`builder/site-reply.mjs`)
  never read the draft: "Took /gallery off the site.", "the old address sends
  visitors to the new one", "roll back … in Cloud → Versions", beside the
  "Saved as draft revision N" fact.
- **Fix.** `inDraft(e)`: the answer's own `checks.draft` (read strictly by
  `readChecks`) or a held draft (`heldDraftOf`). Under it: "Took X off the
  site in the draft; the live site still has it until the owner presses
  Publish."; a move redirects "once the owner presses Publish"; the removal's
  undo is "Nothing is live yet, so a page taken off in the draft can be put
  back if they ask."; a photograph taken off is "no longer on the site in the
  draft; the live site still shows it …", undone by "say “put the photo back”
  before publishing". Live answers keep their wording.
- **Tests:** `test/reply-draft-facts.test.mjs` (removal, move, photo, a look
  with page operations under a held draft, the live control). **Red:** 5 of
  6 fail on `main`'s `site-reply.mjs` (the observer case passes).

## A14-4 — a Build saved as the draft told "the rest of the site is live"

## A14-5 — a bare sweep `recovered` told "Your change was published"

- **Real.** `draftSavedEvidence` was applied only by the request driver; the
  job poll (`GET /api/site/edit/<job>`), which the page reads for a part's
  own reply, served the bare answer, and the page's fixed sentence said
  "published".
- **Fix.** The poll applies `draftSavedEvidence` under draft-first before
  serving a terminal answer (the row is not rewritten; it parses the stored
  body and reads the draft only for a bare `ok` + `recovered`). The page:
  `EditPoll.recoveredMessage(body, draftFirstOn)` says "saved to your draft
  … It goes live when you press Publish." for a proven draft save, a neutral
  "Your change was saved — …" with draft-first on and no proof, and the old
  sentence otherwise; `editReply` and `addonReplyText` use it.
- **Tests:** DOR3 (`test/draft-outcome.test.mjs`) now polls the job and
  reads `reconciled: "draft-saved"` with its revision; a new case in
  `test/edit-poll.test.mjs`. **Red:** both fail on `main`.

## A15-1 — a held media replacement said "Replaced" when nothing was held

- **Real.** Only the answer to `complete` holds a replacement (the REPLACING
  marker, `sealHeld`). A lost answer or the 503 `code: "draft"` went to a
  status read, which answers the stand-in `done` with no `held`; a `done`
  record was kept and reused on the next press, which never called
  `complete`.
- **Fix** (`public/site-media.js`). The start's `replacesInDraft` marks the
  upload `holding` (kept on its record). Such an upload finishes only on an
  answer with `held: true`; a lost or unclear end, or a status `done`, is
  `{ ok: false, code: "draft", error: "couldn’t confirm the new file was
  saved to your draft — check the list, or replace the file again" }` and
  drops the record. A replacement's `done` record is never reused.
- **Left:** the stand-in whose seal failed stays in the library as a file
  (server side, the A10-2 family).
- **Tests:** `test/media-held-replace.test.mjs` (seal failure then a second
  press that holds; a lost answer; no reuse; the switch-off control).
  **Red:** 3 of 4 fail on `main` (the control passes). The media suites
  (`media-client`, `media-recovery`, `media-receipts`,
  `parallel-publish-media`) pass.

## A15-2 — Download zipped another project's or a stale copy

- **Real.** The top bar's Download read `siteCodeFiles` (one list, no
  project, never refreshed after an edit) when it was not empty.
- **Fix.** Download always asks `/api/site/source` for the open site, and
  never writes or falls back to the tab's list.
- **Tests:** `test/site-source.test.mjs`: the warm-cache case now asserts the
  press asks, zips the answer under the open site's name, leaves the tab's
  list alone, and saves nothing when the server cannot answer (the old case
  asserted the defect). **Red:** fails on `main`.

## A15-6 — busy state, live steps and Stop were page-wide

- **Real.** `siteBusy`, `siteBuild`, `siteAbort` carry no origin.
- **Fix.** `siteBusyFor` is set beside every `siteBusy = true` (eight
  places, each with its own project id). `siteBusyHere(site)` draws Stop and
  the live steps (and the build stage) only in that project; `siteStop(site)`
  does nothing elsewhere; another project's Send says "Another project is
  still building — send this once it has finished." and keeps the words.
- **Left for the owner:** sending in another project while a build runs is
  still refused. Allowing it means one busy state per project.
- **Tests:** `test/site-busy-origin.test.mjs`; `test/build-panel.test.mjs`'s
  spelling guard reads `siteBusyHere(site)`. **Red:** fails on `main`.
