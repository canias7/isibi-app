## 5. The switches, as this deploy uploaded them

The Wrangler step's environment prints **`MODEL_REPLIES: on`** and
**`REQUEST_FLOW: off`** in plain text, while every value that comes from a
GitHub secret prints as `***`. So both are the workflow's fallbacks (`||
'on'`, `|| 'off'`), which means neither secret holds a value. Had either been
set to `on` or `off`, every `on` or `off` in the log would print masked, and
neither does (for example `Current Version ID` and `BAND_SPLIT_EVERYONE:
off`). Then `wrangler secret bulk` uploaded both values to the Worker
(`Successfully created secret for key: MODEL_REPLIES`, `… REQUEST_FLOW`).

**This is still the deploy reporting on itself.** No runtime reader reports
these two switches: `/api/site/runtime` names neither (backlog). The live
reading of `REQUEST_FLOW` is the request-mode canary (the plan's Phase D).
