## A37-3 — a long request rewritten from its first 4,000 characters: fixed

- **Real.** Only the page's `reactSend` guard held a rewrite to
  `REWRITE_MAX_CHARS`; with the request flow a part that climbed, exhausted its
  hops, or whose answer routed `build` reached the go-ahead whatever its
  length, and `buildHeld` then sliced the instruction silently.
- **Fix** (`builder/request.mjs`, `askApproval`): a part whose `resume || words`
  is longer than `REWRITE_MAX_CHARS` is never offered; it ends `failed`, why
  `rewrite-too-long`, no job, no charge. `builder/site-reply.mjs` gives that
  reason its own sentence (the bound from `input-budget.mjs`). All three
  approval paths go through `askApproval`, so nothing reaches approval over the
  bound, and `approveRequestPart` has nothing long to approve.
- **Not changed**: `buildHeld` still slices a direct POST's instruction; the
  page guards that path before it sends. Making the build route refuse instead
  is a new refusal on a public route and is left for the owner.
- **Test** (`test/request-plan.test.mjs`, "A37-3 — …"): a 4,000+-character
  answer routed `build` ends `rewrite-too-long` and is not offered; the reply
  names 4,000; exactly 4,000 is still offered.
- **Red check**: fails on the old `request.mjs` and on the old `site-reply.mjs`.
- **Sweep**: 4 of 4 killed (`>=` for `>`; `resume` ignored; still offered;
  sentence names no bound), comment-only control survived.

## A02-2 — change-0 dependencies mapped by `made[i - 1]`: fixed

- **Real.** `carveParts` returned only the new parts, and both callers (a
  routing job's answer in `settle`, an answer's routing in `answerPart`)
  mapped the router's numbers with `made[i - 1]`; a skipped entry before the
  one named shifted or dropped the need.
- **Fix** (`builder/request.mjs`): `carveParts` returns its change-to-part map
  as a non-enumerable `byChange` on the array it already returns (so existing
  callers and deep-equal tests see the same list), resolving an entry that
  already is a part (not the parent) to that part. Both callers map through
  it, skipping the part itself and a part that already waits on it (no loop).
- **Test** (`test/request-plan.test.mjs`, "A02-2 — …"): the audit's probe
  (a first entry with a trailing full stop, `after: [2]`) through `nextStep`;
  a paraphrased first entry through `answerPart`; an existing part resolved.
- **Red check**: fails on the old `request.mjs`.
- **Sweep**: 4 of 4 killed (index shifted back; answer path drops the map;
  existing part not resolved; empty map), comment-only control survived.

## A03-5 — the tweak's compile fall-through cannot happen: real, left

- **Real**: `publishStep` answers `{ ok: true, deferred: true }` outside a
  preparation, so `if (twPub.ok)` always holds and the rewrite fall-through is
  dead; the compile happens once in `publishSpine`, with no rewrite retry.
- **Left for the owner**: the two fixes the audit names cost differently
  (compile the tweak before accepting it: container time on every tweak; or
  retry with the rewrite writer after the spine's compile fails: a second,
  stronger and dearer page call). Which one, if either, is a product decision.
- **Changed**: only the comment above `if (twPub.ok)` in `worker.js`, which
  promised the fall-through; it now says it cannot happen and why. No behavior
  change, so no guard or sweep.
