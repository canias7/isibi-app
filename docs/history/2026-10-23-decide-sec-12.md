## A16-4 (#140): a job could take another site's address

Owner's choice (a): alias writes go through a Worker-side check that refuses a
name owned by another site, or equal to another site's storage name (slug).

What A33-9 already had (`claimsOwn`, `builder/job-gateway.mjs`): before a job's
`site_aliases` POST is forwarded, the names' alias rows are read with the
service key, and the write is refused (`why: "claim"`) when any row is another
site's or the read fails. That already covers a merge-duplicates upsert onto
another site's existing alias row.

The gap this closes:

- **A plain insert of an unused name equal to another site's slug.** The rule
  now carries `storage: "site_backends"`, and `claimsOwn` also reads
  `site_backends?slug=in.(<names>)&select=slug`. Any row that is not the job's
  own site refuses the write. A failed read, a thrown read or a body that is
  not a list refuses it too (fail closed).
- **A query on a claiming write.** A `site_aliases` POST now takes no query at
  all (`why: "query:<name>"`), so `on_conflict=<another column>` or `columns=`
  cannot change which row a merge lands on. The name is the conflict target by
  itself. No caller sends a query here (`putAliasRow` posts a bare
  `/rest/v1/site_aliases` with `Prefer: resolution=merge-duplicates`).

Container renames keep working: both of `renameRows`'s rows (demote, promote)
are forwarded, with merge-duplicates, including a rename back to the site's own
slug, because its own `site_backends` row is allowed.

**Still open (as A33-9 recorded):** a read-then-write race, where two claims
land in the same instant. Closing it needs an RPC that inserts or updates only
the caller's own rows, which is a SQL migration the owner applies.

## A16-7 (#142): the probe routes were open to any signed-in account

Owner's choice (a): an operator allowlist.

- `worker.js`: `operatorRefusal(request, env)` returns 401 when the caller is
  signed out and 403 unless their user id is in `OPERATOR_UIDS`. The value is
  read as uuids separated by commas or spaces, in any case. Any other entry is
  dropped, so empty, missing, `-`, `*` or a mistyped value refuses everyone.
- It gates exactly `/api/_slow`, `/api/_hold`, `/api/_egress` and
  `/api/site/job-probe` (GET and POST). `/api/site/build-health` and
  `/api/site/runtime` stay as they were: any signed-in owner. That means the
  edit canary's normal free check is unchanged.
- `.github/workflows/deploy.yml`: `OPERATOR_UIDS` is in the `secrets:` list as
  `${{ secrets.OPERATOR_UIDS || '-' }}`. **The fallback is `-`, not `''`**:
  `wrangler-action` fails on an empty value as it does on a missing one
  (`test/deploy-secrets.test.mjs` refuses `|| ''`, as on 2026-09-01). `-`
  parses to no uid, so the result is the same: everyone is refused.
