# Phone apps on Expo: the plan (2026-10-21, for the owner's approval)

The owner: *"we need the real deal, the correct framework just like we did for
the site"*. Today an app is a website inside an app shell (Capacitor). This
plan replaces that with real iPhone and Android apps written in **React Native
with Expo**, built by **Codemagic**. The open-source Expo code is used and EAS,
Expo's paid service, is not.

## What stays exactly the same

The chat, the router, the Make: picker, the design step, versions and drafts,
Publish, credits, the edit ladder's shape, and the site's database. An app is
the same process as a site with a different output (owner, 2026-10-20).

## The stack

| Part | Site today | App |
|---|---|---|
| UI library | React 19 | React Native (Meta, MIT) |
| Framework: screens, routing, build | TanStack Start + Vite | Expo + Expo Router (MIT) |
| Styling | Tailwind v4 | NativeWind (Tailwind classes for apps, MIT) |
| Components | our kit, 2,112 | **our app kit** (new) |
| Preview in the builder | the site frame | Expo's web version, in the two phones |
| Preview on a real phone | — | Expo Go QR code (optional) |
| Installable app | — | Codemagic: builds and signs on Macs, TestFlight, stores |

## Phases

Each phase ends with screenshots, tests, records, and a merge only on your word.

**Phase A — the app kit (no model calls).**
- A pinned Expo template in `builder/expo/template/`, laid out like the site kit.
- Our app components:
  - tab bar and screen header;
  - list rows, cards and chips;
  - steppers and toggles;
  - a bottom sheet;
  - open-now and hours;
  - a product list and an order form;
  - a booking form.
- The theme comes from the same design step, so an app gets the site's look.
- Delivers: the kit compiles, and a hand-written app made from it renders in the phones.

**Phase B — the container checks the app.**
- An app container (the Android one, reused) that checks a model-written app the way sites are checked:
  - `tsc`;
  - Expo's web export;
  - a Chromium render check of every screen.
- The web version is stored like a draft, so the two phones show it.
- Delivers: the phones show a real app from stored source.

**Phase C — the model writes apps (the first paid runs).**
- App page rules: screens with Expo Router and our app kit, never `<div>`.
- The design step plans 3–5 screens, with the tabs taken from them.
- The same build route, with `surface: "app"` choosing the app writer.
- Delivers: a chat message builds a real app, shown in the phones. About 1–3 approved runs at a quoted cost.

**Phase D — installable apps through Codemagic.**
- **Download Android app** and **Get iPhone app** send the source to Codemagic. Codemagic builds and signs both apps; the iPhone app goes to TestFlight.
- The Capacitor Android container is retired once Codemagic's Android build is proven.
- Needs: your Apple Developer and Codemagic accounts, and the Codemagic token as a secret.

**Phase E — data and edits.**
- An app reads and writes the project's database through the same `/api/db/<slug>/` route, at its full address.
- Edits work on app screens: text and data first, then the look and the screens themselves.

## Decisions that are yours

1. Approve this stack: React Native + Expo (open source), NativeWind and Codemagic.
2. Whether one project can hold both a site and an app, sharing the database. This affects Phase E.
3. When to make the Apple Developer and Codemagic accounts (needed by Phase D).

## Evidence so far

A hand-built Expo demo of Harbour Loaf (Today, Loaves, Order with a bottom
sheet, Hours) was exported to the web and photographed in phone frames on
2026-10-21. It used no model calls and no credits, and nothing was committed
from it.
