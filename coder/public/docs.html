Coder

Coder is an AI that works on your code in your own GitHub, the way a developer would at a terminal. You ask in plain English; it reads your code, runs commands, makes the changes, and saves them to its own branch.

  • It works on your repositories, through Coder's GitHub app. You choose which ones on GitHub.
  • It never touches your main branch. Each chat saves to its own branch, and Coder opens a pull request when you ask.
  • It runs on its own Linux machine, one per chat, with the usual developer tools installed.

How a chat works

  • Start a chat with New chat and pick a repository. Before your first message you can add up to three more repositories to the same chat; Coder works on each in its own folder, side by side.
  • Each message is a job. Coder works through it step by step (reading files, running commands, changing code), and you see every step in the chat as it happens. It finishes by answering in words.
  • Its work is saved to the chat's branch at the end of each job. You can close the tab; the job keeps going.
  • The chat's machine keeps its files between messages, including what Coder installed and its /tmp folder, and sleeps when the chat is quiet.

Read Tested

Read opens a file in your project and shows it to Coder with line numbers, the way you'd see it in an editor. It never changes anything.

Text files

  • A whole file comes at once when it fits: up to about 100,000 characters.
  • A bigger file comes in parts. The first part ends with a note, such as [PARTIAL view: lines 1-1111 of 1561 (about 90 KB of 127 KB). Read more with offset 1112 and limit 450. …], and Coder reads on before it answers.
  • A file over 256 KB isn't read whole in one go: Coder reads the part it needs, or searches it first.
  • Lines are never cut. A single line too long for one read is read on its own.
  • Files in UTF-8 and UTF-16 are read as text. A file saved in an old text format (such as Windows-1252) shows the letters it can't decode as �, with a note telling Coder not to change it with its tools, so the real letters are never lost.

Pictures

  • PNG, JPEG, GIF, WebP, BMP and TIFF, up to 128 MB. Coder sees the picture, and a small copy shows under the step in your chat.
  • A big picture is shown at up to 2,000 pixels. Coder is told its real size, how to map a spot back onto it, and how to crop a part for fine detail.
  • Pictures you paste or attach are saved in your project's .coder-pictures folder (never saved to your branch), so Coder can open them again later in the chat.

PDFs

  • Up to 10 pages are read whole. A longer PDF is read by page ranges, at most 20 pages at a time.
  • Coder sees every page as a picture as well as its text, so charts and layouts aren't missed. The first pages show small under the step.
  • A password-protected or broken PDF says so, and Coder counts a PDF's real pages, even when the file says otherwise.

Notebooks

  • Jupyter notebooks (.ipynb) come as their cells, with each cell's output, charts included.

What read won't open

  • A folder: Coder lists what's in it instead.
  • Binary files such as .zip or .xlsx: Coder is told a way to read each kind.
  • Pipes and devices, and anything outside your project, including a link that points out of it.

Files you mention with @

  • Type @ and a file's name in your message, and the file goes into the message, so Coder has it right away. Files whose name matches come first in the list.
  • A folder comes as its list of files, and a picture is shown. A file too big for one read is named, and Coder reads the part it needs.

What Coder is told on its own

  • A missing file comes with the folder Coder is in, so a wrong folder is easy to spot.
  • If one of Coder's commands changes a file it has read (a command that shows a file, such as cat, counts as reading it), Coder is told, with the lines that changed.
  • After a long chat is summarized to make room, Coder reads again up to five files it was working on, newest first.

Write Testing

Write makes a new file, or replaces a whole file with new content. For a change to part of a file, Coder uses edit.

  • Up to about 90,000 characters at a time. A longer file is written in parts: the start first, then the rest added with edit.
  • A file in UTF-16 stays UTF-16.

When write says no

  • A file Coder has only seen part of, or a notebook it hasn't read: Coder reads it first, so nothing it never saw is lost.
  • A file in an old text format: writing would lose its real letters, so Coder changes it with a command that keeps its format, or asks you about converting it.
  • A shortcut (link) to another file: write names the real file instead, so Coder always knows which file it's changing.
